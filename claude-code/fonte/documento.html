Antes de tudo

O chat conversa sobre o seu trabalho.
O Claude Code faz o trabalho — no seu ambiente, com a sua permissão.

Mesmo cérebro, mãos diferentes

Os dois usam os mesmos modelos Claude. A diferença não está na inteligência, e sim no alcance dela. No chat, o Claude responde com texto — e, quando executa código, faz isso num contêiner isolado na nuvem, separado dos seus sistemas. Quem abre os arquivos, copia, cola, executa e testa é você.

O Claude Code coloca o mesmo modelo dentro do que a documentação chama de harness agêntico: ferramentas para ler e editar arquivos, pesquisar o código, rodar comandos no terminal, usar o git e consultar a web. Com elas, ele trabalha em ciclo até a tarefa ficar pronta — e você acompanha e aprova.

O ciclo que faz a diferença

Quando você passa uma tarefa, o Claude Code trabalha em três fases que se repetem: coletar contexto, agir e verificar o resultado. Cada ação gera informação nova, que decide o próximo passo — ele encadeia dezenas de ações e se corrige pelo caminho.

“Embora seja excelente em código, ele ajuda em qualquer coisa que se faça pela linha de comando: escrever documentação, rodar builds, pesquisar arquivos, investigar assuntos e muito mais.”

Parte 1 · Na prática

O mesmo problema, dois mundos

Situação clássica: depois do último deploy, a API começou a responder erro 500. Veja como a investigação acontece em cada ferramenta.

No chat

Você é o intermediário

  1. Você descreve o problema e cola o trecho de log que parece relevante.
  2. O Claude levanta hipóteses e pede mais dados: a configuração, a versão, o código da rota.
  3. Você abre os arquivos, copia e cola na conversa — torcendo para não ter esquecido nenhum.
  4. Recebe uma correção e aplica à mão, arquivo por arquivo.
  5. Roda os testes. Algo quebra. Copia o erro e volta ao passo 2.
Cada volta do ciclo passa por você: olhos, mãos e Ctrl+C / Ctrl+V.
No Claude Code

Você é o revisor

$ claude "A API retorna 500 desde o último deploy. Investigue e corrija."
  1. Lê os logs e o git diff do deploy para ver exatamente o que mudou.
  2. Rastreia a causa pelo código — por exemplo, uma variável de ambiente renomeada no código, mas não na configuração.
  3. Propõe a correção e mostra o diff; você aprova.
  4. Roda os testes e confirma que passam.
  5. Faz o commit com mensagem descritiva e, se você pedir, abre o pull request.
Você define o objetivo e aprova as ações. O trabalho braçal fica com ele.
Resposta do chatUma hipótese bem fundamentada — que você ainda precisa aplicar e testar.
Resposta do Claude CodeUma correção já aplicada e testada no seu ambiente real.

Pedidos que funcionam muito bem no Claude Code

“Escreva testes para o módulo de autenticação, rode e corrija as falhas.”
“Analise os logs do nginx da última hora e me diga de onde vêm os erros 502.”
“Este script de backup em PowerShell parou de funcionar ontem. Descubra o porquê.”
“Atualize as dependências, rode a suíte de testes e me mostre o que quebrou.”
“Explique a arquitetura deste repositório como se eu tivesse acabado de entrar no time.”
“Crie um Dockerfile e um docker-compose para este serviço e valide o build.”

E quando o chat ainda é a melhor escolha?

  • Perguntas rápidas e conceituais (“RAID 5 ou 10?”)
  • Escrever e revisar textos, e-mails e propostas
  • Analisar um PDF ou uma planilha avulsa
  • Pesquisa e brainstorming

Regra prática: se a resposta vai virar arquivo, comando ou commit, é trabalho para o Claude Code.

Parte 2

Por que o Claude Code rende mais

Dez argumentos práticos para quem trabalha com TI — do fim do copiar-e-colar à automação no CI.

01

Fim do copiar-e-colar

No chat, o Claude só enxerga o que você cola. Aqui ele lê o projeto, roda os comandos e lê a saída sozinho. O tempo gasto transportando contexto vira tempo de decisão.

02

Ele confere o próprio trabalho

Roda os testes, lê o erro, corrige e roda de novo até a tarefa fechar. A resposta deixa de ser um palpite e vira um resultado testado.

03

Contexto real, não fragmentos

Entende como os arquivos se conectam e edita vários de uma vez. Com um plugin de LSP, vê erros de tipo logo após editar e navega por definições, como a sua IDE.

04

Fala a língua do terminal

Segue a filosofia Unix: entra em pipes, scripts, cron e CI.

$ tail -200 app.log | claude -p "aponte anomalias nestes logs" $ git diff main --name-only | claude -p "procure falhas de segurança"
05

Vai muito além de programar

Se dá para fazer pela linha de comando, ele também faz: scripts Bash e PowerShell, análise de logs, Docker, configurações, documentação, migrações, auditoria de dependências.

06

Memória de projeto versionada

O CLAUDE.md guarda padrões, comandos de build e regras do tipo “nunca faça X”. É lido em toda sessão e vai para o git: o time inteiro compartilha o mesmo contexto.

07

Conecta com as suas ferramentas

Via MCP, o padrão aberto de integração, consulta o banco de dados, atualiza tickets no Jira, lê o Google Drive e o Slack ou usa a ferramenta interna da empresa.

08

Automação de verdade

Hooks garantem ações em todo evento (formatar após editar, bloquear comandos perigosos). No CI, revisa PRs via GitHub Actions ou GitLab. Rotinas agendadas rodam até com o PC desligado.

09

Trabalho em paralelo

Subagentes pesquisam em contexto isolado e devolvem só o resumo. Rode várias sessões ao mesmo tempo, comece uma tarefa no celular e continue no terminal depois.

10

Sem custo extra

Incluído nos planos Pro, Max, Team e Enterprise. Quem já assina o Pro (US$ 20/mês, ou US$ 17/mês no anual) já tem — no app desktop, é só abrir a aba Code.

Parte 2 · Segurança

“Deixar uma IA rodar comandos na minha máquina?”

É a primeira pergunta de qualquer profissional de TI — e a resposta está no desenho da ferramenta. Você escolhe quanta autonomia dar, e as regras são aplicadas pelo próprio Claude Code, não pelo modelo: não dependem da “boa vontade” da IA.

ModoO que roda sem perguntarQuando usar
ManualSó leituras. Ele pede permissão antes de editar arquivos, rodar comandos ou acessar a redeTrabalho sensível, código desconhecido
Accept editsLeituras, edições e comandos simples de arquivos (mkdir, mv, cp)Iterar em código que você está revisando
PlanSó explora e propõe um plano; não edita seus arquivos até você aprovarEntender o problema antes de mexer
AutoTudo, com um classificador — um segundo modelo — revisando as ações em segundo plano e bloqueando as arriscadasTarefas longas, sem aprovar cada passo

Shift+Tab alterna entre os modos. Nas versões recentes, as sessões no terminal começam no Auto; quem prefere aprovar tudo usa o Manual. Para CI existe o dontAsk (só roda o que estiver pré-aprovado); o bypassPermissions, que pula as checagens, é só para contêineres e VMs isolados.

Regras allow / ask / deny

Por ferramenta e por comando, versionadas em .claude/settings.json. Regras de deny valem em todos os modos.

{ "permissions": { "allow": ["Bash(npm run *)", "Bash(git commit *)"], "deny": ["Bash(git push *)", "Read(./.env)"] } }

Sandbox no sistema operacional

Restringe o acesso dos comandos de shell a arquivos e à rede no nível do SO — e continua valendo mesmo que uma injeção de prompt engane o modelo.

Checkpoints

Antes de editar um arquivo, ele salva o estado anterior; Esc duas vezes volta atrás. Ações em sistemas remotos (bancos, APIs, deploys) não têm checkpoint: essas você controla pelas permissões.

Travas que nenhum modo ignora

Remoções com rm/rmdir em caminhos críticos e ações cobertas por uma regra de ask nunca são aprovadas automaticamente — em nenhum modo, nem no bypassPermissions.

Limites ditos na conversa

Se você disser “não faça push” ou “espere minha revisão antes do deploy”, o classificador do modo Auto bloqueia as ações correspondentes até você liberar.

Políticas da empresa

Configurações gerenciadas (managed settings) que o usuário não sobrescreve: desativar modos, liberar ou bloquear marketplaces de plugins e forçar a instalação dos aprovados.

Histórico auditável

Cada mensagem, ação e resultado fica salvo localmente em texto puro (JSONL, em ~/.claude/projects/): dá para auditar, retomar e bifurcar sessões.

Parte 3

Plugins: o gerenciador de pacotes

Um plugin é uma pasta de componentes — skills, subagentes, hooks, servidores MCP e outros — que o Claude Code instala e carrega como uma unidade. Para quem é de TI, a analogia é imediata: é o apt, o npm ou o brew das capacidades do Claude.

Marketplace≈ repositório de pacotes
Um catálogo — um arquivo marketplace.json num repositório git — que lista os plugins e de onde baixar cada um. O oficial da Anthropic já vem configurado.
Plugin≈ pacote
Uma pasta com manifesto (.claude-plugin/plugin.json): nome, versão, descrição e os componentes.
/plugin install≈ apt install
Instala com um comando, como /plugin install commit-commands@claude-plugins-official, e recebe atualizações do marketplace.
Escopos≈ global × por projeto
User: em todos os seus projetos. Project: para todo mundo que trabalha no repositório. Local: só para você, só naquele repositório.

Anatomia de um plugin

meu-plugin/
A pasta inteira é instalada, atualizada e carregada como uma unidade.
├── .claude-plugin/plugin.json
Manifesto — nome, versão e descrição do plugin.
├── skills/review/SKILL.md
Skill — instruções que o Claude carrega quando são relevantes; aqui, vira o comando /meu-plugin:review.
├── agents/security-reviewer.md
Subagente — especialista com contexto próprio, para quem o Claude delega tarefas.
├── hooks/hooks.json
Hooks — ações garantidas em eventos: rodar o linter após cada edição, bloquear arquivos protegidos.
├── .mcp.json
Servidores MCP — ferramentas de sistemas externos: banco de dados, Jira, Slack.
├── .lsp.json
Servidores LSP — erros de tipo e navegação por símbolo, como na IDE.
├── monitors/monitors.json
Monitors — comandos em segundo plano (como tail -F error.log) que avisam o Claude.
└── bin/
Executáveis — scripts no PATH enquanto o plugin está ativo, como o CLI interno da empresa.

Nenhum componente é obrigatório: cada plugin usa só o que precisa. Também pode trazer estilos de resposta (output styles), temas de cores e configurações padrão.

Parte 3 · Vantagens

As vantagens dos plugins

O que transforma peças soltas em algo instalável, versionado e compartilhável.

01

Setup completo em um comando

Em vez de configurar skills, hooks e integrações um a um, você instala um pacote pronto e testado — que se atualiza sozinho pelo marketplace oficial.

02

O time inteiro no mesmo padrão

No escopo de projeto, o plugin fica no .claude/settings.json do repositório: cada pessoa instala uma vez e o time inteiro trabalha com o mesmo fluxo, hooks e integrações.

03

Modular e transparente

Desative sem desinstalar, veja o que está parado e, antes de instalar, quantos tokens o plugin adiciona a cada mensagem. Comandos em namespace evitam conflitos.

04

Reaproveitamento entre projetos

Empacote o setup de um repositório e leve para os outros — ou publique no marketplace da empresa, em qualquer repositório git (GitHub, GitLab, servidor interno).

05

Governança corporativa

Por configurações gerenciadas, a empresa libera ou bloqueia marketplaces e força a instalação dos plugins aprovados.

06

Ecossistema em crescimento

Marketplace oficial (Anthropic e parceiros como GitHub, Atlassian, Slack, Figma, Vercel e Supabase), marketplace da comunidade e de terceiros.

Por onde começar: plugins que valem a instalação

Seleção do marketplace oficial. Os de fluxo têm o selo “Anthropic verified”.

Fluxo de trabalho

  • Commit Commands — commit, push e criação de pull request
  • Code Review — revisão com agentes especializados e filtro por nível de confiança
  • PR Review Toolkit — revisa comentários, testes, tratamento de erros, tipos e qualidade
  • Feature Dev — desenvolve features com agentes de exploração, design e revisão
  • Security Guidance — hook que alerta sobre injeção de comandos, XSS e padrões inseguros
  • Code Simplifier — simplifica e refina o código alterado recentemente
  • CLAUDE.md Management — audita o CLAUDE.md e registra aprendizados
  • Claude Code Setup — analisa o projeto e recomenda automações sob medida

Integrações

  • GitHub — servidor MCP oficial para gerenciar repositórios
  • Atlassian — Jira e Confluence: issues, documentação e sprints
  • Slack — servidor MCP oficial do Slack
  • Playwright — automação de navegador e testes end-to-end (Microsoft)
  • Context7 — documentação atualizada de bibliotecas, consultada na hora
  • Supabase — banco, autenticação e storage; roda SQL
  • Chrome DevTools — controla e inspeciona um Chrome em execução
  • Figma — lê arquivos de design e traduz componentes em código

Instalar e gerenciar

> /plugin # painel: Discover, Installed, Marketplaces > /plugin install commit-commands@claude-plugins-official > /plugin marketplace add sua-empresa/plugins # marketplace do time (repo git) $ claude plugin list # no shell: instalados e escopos $ claude plugin disable nome@marketplace # desliga sem desinstalar

Plugin é código. Ele roda com os seus privilégios de usuário. Antes de instalar, o painel mostra tudo o que ele adiciona (comandos, agentes, hooks, servidores MCP e LSP). Os marketplaces oficiais são da Anthropic; marketplaces de terceiros não passam pela revisão dela — instale só de fontes em que você confia.
